## Codex setup recommendation for a later, separately authorized change

OpenAI's [Skill guidance](https://developers.openai.com/blog/skills-agents-sdk) describes `AGENTS.md` for repository policy and `.agents/skills/<name>/SKILL.md` for task-specific workflows; Codex reads Skill metadata first and full instructions when relevant. The existing [LUC Skill](../../../skills/luc-ui/SKILL.md) and `.context` handoff remain authoritative. Keep external material in reviewed, pinned folders and give each a narrow trigger. Do not flatten third-party rules into root `AGENTS.md`. [OpenAI Skills documentation](https://developers.openai.com/api/docs/guides/tools-skills) also recommends reviewing supporting files before making a Skill available.

1. **First choice:** later install/review `frontend-design`, `web-design-guidelines`, and `vercel-composition-patterns` in a Codex-discovered location, recording commit SHA, upstream URL, license, and review date. The external Skill instructions must be subordinate to [DESIGN_SYSTEM.md](../../../DESIGN_SYSTEM.md), [AI_DESIGN_GUIDE.md](../../../AI_DESIGN_GUIDE.md), and the package public API.
2. **Reference shelf:** keep `vercel-react-best-practices` and UI UX Pro Max as linked/pinned reference material until a specific performance or concept-generation task calls for them. This avoids broad trigger overlap with the LUC Skill and generic aesthetic recommendations.
3. **Verification before install:** inspect every `SKILL.md`, referenced script and install manifest; compare the upstream directory with the generated payload; check license and a pinned commit; use a dry-run/list option only after reviewing the CLI behavior. Do not pipe remote shell scripts to a shell or run `npx` installers during this research task. [Vercel CLI documentation](https://github.com/vercel-labs/skills/blob/main/README.md), [UI UX Pro Max README](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/README.md).

The Skills are guidance, not code assets. They should lead an agent to inspect LUC's existing `Card`, `Tabs`, `SharedHighlight`, `DataTable`, `Workspace`, and chart composition before suggesting a new component. Their third-party text cannot change repo boundaries or license policy.
