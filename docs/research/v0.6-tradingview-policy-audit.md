Two widgets were **not** in the brief's expected list and were discovered during
the audit: the **Brokers** category (Broker Rating, Broker Reviews) and the
**World Market Summary** widget. Both are wrapped.

### The broker widgets are partner embeds

They are Web Components, but the broker id is part of the **script URL**
(`/widget/broker-rating.js?locale={locale}&broker={broker}`), so two brokers on
one page are two modules. They also require a `blob:` source in the page's
`img-src` CSP for the award images. LUC wraps both, documents the extra CSP
requirement, and keeps them out of the market-widget patterns.

## 3. Terms, attribution and branding

Read from the provider's own pages; these are the rules the implementation
encodes.

1. **The copyright block is part of the embed.** Every generated iframe snippet
   includes
   `<div class="tradingview-widget-copyright"><a …><span class="blue-text">…</span></a><span class="trademark"> by TradingView</span></div>`,
   and the embed script injects its own styles for it. LUC reproduces that block
   verbatim, links and all.
2. **Symbol links are the only redirectable links.** From "Customize links":
   *"Only symbol links can be customized. Links to data sources (attributions),
   the TradingView logo, and legal/branding links always point to their original
   destinations and cannot be overridden."*
3. **`symbol-url` accepts `https://` and `http://` only**; anything else is
   silently rejected by the provider and falls back to the TradingView URL. LUC
   passes the template through unchanged and never builds one from user input.
4. **Web Components are closed shadow roots.** *"All widgets are built with
   closed shadow roots, meaning you cannot style widgets' internal elements
   directly."* The three supported customisation paths are the `theme`
   attribute, the published CSS custom properties, and documented `::part()`
   selectors. LUC uses exactly those three and nothing else.
5. **The `theme` attribute is all-or-nothing**: without it a widget follows the
   page's `color-scheme`; with it, it is locked. LUC sets it explicitly and
   re-renders it on a theme change.
6. **Automatic sizing is the recommended approach** — the widget fills its
   container. LUC gives every wrapper a definite box height.
7. **`overflow: hidden` clips provider pop-ups.** LUC never sets it on a widget
   box.
8. **A horizontal Ticker Tape defines its own height** and will not stretch.
9. **CSP (broker widgets only):** the provider's own page requires
   `img-src 'self' blob:;` for broker award images.

Derived from the provider's generated snippets **and** from the requests
observed while loading one widget of each format:

| Domain | Used for |
| --- | --- |

| `widgets.tradingview-widget.com` | Web Component modules and chunks |
| `www.tradingview-widget.com` | iframe content, broker scripts |
| `s.tradingview.com` | iframe content |
| `widget-sheriff.tradingview-widget.com` | provider-side embed policy check, called by the Web Components |

LUC loads nothing from these hosts until a wrapper renders, and a product that
never imports `@luc/ui/tradingview` loads none of them.

## 5. Privacy boundary

Rendering a widget loads third-party resources in the visitor's browser and
gives TradingView the visitor's IP and user agent. Whether that needs consent,
a cookie banner or a different regional treatment is the **consuming product's**
decision; LUC documents the behaviour and draws no legal conclusion.

## 6. Rejected approach: scraping

The provider's widgets are explicitly **display** integrations. LUC does not:

- read values out of a widget or its shadow DOM,
- use widget content as a data API,
- proxy widget data into ClickHouse or any other store,
- reverse-engineer private endpoints.

Anything that must exist as a number in LUC's own analytics comes from LUC's own
data pipeline.

## 8. Provider bugs found during integration QA

Recorded because they shape the wrapper contracts:

1. `tv-economic-map` throws (`D[this.region] is not iterable`) when `region` is
   not one of `global`, `africa`, `asia`, `europe`, `north-america`,
   `south-america`, `oceania` and renders nothing useful afterwards. LUC types
   `region` as that closed union.
2. `tv-economic-map` throws (`Cannot read properties of undefined`) when `metric`
   is not one of `gdp`, `ur`, `gdg`, `intr`, `iryy`. LUC types it as that closed
   union and exposes the provider's labels for each key.
3. `useDirtyRect` — see `docs/CHART_GUIDE.md` §6a for the LUC-side chart finding
   from the same QA pass.

Both provider errors are raised inside the provider's own module (`firstUpdated`
in `tv-economic-map.js`), are not catchable from the host page, and are the
reason those two props are closed unions rather than `string`.
