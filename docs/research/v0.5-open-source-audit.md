# LUC UI V0.5 — open-source audit

Scope: the application layer (shell, navigation, workspace, URL state) and
package hardening. Everything below was read on **2026-09-26**; versions and
licenses were verified against the registry and the repositories themselves, not
recalled.

The rule for the round: **research widely, depend narrowly.** Five projects were
studied closely and one was installed.

## Adopted

### bvaughn/react-resizable-panels — 4.13.3 — MIT

`DIRECT_DEPENDENCY` (resizable workspace).

- **Studied:** the current v4 API (`Group`/`Panel`/`Separator`, not the older
  `PanelGroup`/`PanelResizeHandle`), `defaultLayout` persistence,
  `onLayoutChanged` with an `isUserInteraction` flag, collapsible panels,
  `collapsedThreshold`, imperative `Group`/`Panel` handles, `separator`
  attributes, `resizeTargetMinimumSize` for coarse pointers, SSR notes.
- **Lessons that shaped the implementation:**
  - The engine sets `display: flex` **inline** on its roots, so a pane cannot be
    hidden with a class — which is why `Workspace` switches *composition* for
    stacked and focus modes instead of toggling CSS.
  - `Separator` already renders `role="separator"`, `aria-valuenow/min/max`,
    `tabIndex=0` and arrow-key resizing, and it exposes its state as
    `data-separator="inactive|active|focus"`. LUC styles that attribute rather
    than keeping a second state machine.
  - `Panel`'s `className` lands on a nested div, and a group's children must be
    panels/separators directly.
  - Its `useDefaultLayout` defaults `storage` to `localStorage`, evaluated when
    the hook is called — so LUC keeps its own versioned, SSR-safe persistence
    (`usePersistentState`) instead.
- **Used:** panes, separators, constraints, keyboard resize, imperative
  collapse/expand. **Not used:** `useDefaultLayout`, `SeparatorOverlay`.

### 47ng/nuqs — 2.10.1 — MIT

`DIRECT_DEPENDENCY` in the **Showcase only** (framework adapter).

- **Studied:** typed parsers, `createParser`, `useQueryState(s)`,
  per-call `history`/`shallow`/`scroll`/`clearOnDefault`, the App Router adapter,
  the testing adapter, and the server-side loaders.
- **Decision:** `@luc/ui` must not hardcode Next. The library keeps the
  vocabulary — codecs, parameter sets, deterministic serialization — and stays
  router-agnostic; nuqs supplies the App Router plumbing behind a four-line
  adapter (`apps/showcase/lib/luc-nuqs.ts`). A product on another router
  implements `UrlStateAdapter` and does not install nuqs at all.
- **Verdict:** the optional-integration shape the brief asked for. It is a
  Showcase dependency, so a consumer pays nothing for it.

### rolldown/tsdown — 0.23.0 — MIT (dev)

`DIRECT_DEPENDENCY` (dev) for the package build.

- **Studied:** multi-entry builds, `unbundle` (one output module per source
  module), `dts`, `platform`, `external` defaults, the optional `publint`/`attw`
  integrations, and the `unrun` config loader (which is why `unrun` is a dev
  dependency).
- **Compared with:** Vite library mode, `unjs/unbuild`, `egoist/tsup`, and plain
  `tsc`.
  - `tsc` cannot rewrite extensionless relative specifiers, which leaves Node
    resolvers unhappy.
  - `unbundle: true` is what makes the subpath promise real, and it keeps
    `"use client"` on every module that had it (verified after each build, and
    re-inserted by the post-build script if a bundler ever drops it).
  - Vite, and in particular a per-entry bundling strategy, produced a bigger,
    less inspectable output for this package.
- **Used:** build only. Its `exports: true` generator was deliberately not used:
  a hand-curated map is the difference between a public surface and "every
  internal file, published".

### publint — 0.3.24 — MIT (dev) and @arethetypeswrong/cli — 0.18.5 — MIT (dev)

`DIRECT_DEPENDENCY` (dev) for package validation. `publint` runs against the
**packed tarball** (`pack: "pnpm"`), so it validates the published manifest
rather than the repository one — which is the only way to catch a
`publishConfig` mistake. `attw` was evaluated and folded into the same script:
it reports false positives on CSS export entries, so CSS subpaths are excluded
from its report and checked by the file-existence test instead.

## Studied, not adopted

### shadcn-ui/ui — sidebar and application-shell patterns

`DESIGN_REFERENCE`.

Read for architecture only: a sidebar with `collapsible="icon"`, a provider
holding state and a cookie, group/menu composition, a rail, and a mobile Sheet
driven from the same tree. Useful lessons that are visible in the LUC
implementation: the rail keeps labels reachable, in-shell navigation closes the
drawer, and the shell owns the scroll model.

Not adopted: the visual identity (LUC's rail, active edge, hairline language and
density are its own), and the cookie-based persistence (LUC uses a versioned
local adapter so it can be opted out of entirely).

### shadcn-ui/lint — 0.2.0 — MIT

`REFERENCE_ONLY`, **deferred to V1.0**.

This is the mature version of the "design contracts agents can verify" idea:
`no-restyle` with per-component contracts, `no-raw-colors`, and errors that
suggest the right token. It is a genuinely good fit for a repository developed
through coding agents.

It is not adopted yet for three concrete reasons: it is 0.2.x; it needs a
hand-written contract per component (LUC has ~40 component families with
variants) before it says anything useful; and `eslint --max-warnings 0` turns
every rule into a hard gate, so a half-configured ruleset would block the repo
rather than guide it.

Instead, two rules that pay for themselves today were written natively
(`eslint-rules/no-raw-color-literals.mjs`): `no-raw-color-literals` and
`no-deep-package-imports`. They run in both packages. The first real violation
they found was the Next `themeColor` viewport metadata, which is now a
documented, justified exception. **V1.0 recommendation:** adopt `@shadcn/lint`
and port those two rules plus `no-restyle` contracts for the ten most-used
components.

### radix-ui/primitives

`DIRECT_DEPENDENCY` already (v1.6.7, MIT). V0.5 added one new use: `Collapsible`
for nested navigation, so `aria-expanded`/`aria-controls` and the height
animation are the library's. No new primitive stack was added for menus,
navigation or scroll areas — `Sheet`, `Popover`, `Tooltip`, `DropdownMenu` and
`ScrollArea` were already there.

### mui/base-ui, ariakit/ariakit, tailwindlabs/headlessui, adobe/react-spectrum

`DESIGN_REFERENCE` / `ACCESSIBILITY_REFERENCE`.

Read for navigation semantics, breadcrumb structure, disclosure and focus
behaviour, and resizable-panel accessibility. React Spectrum's date and table
work is already a dependency through `react-aria-components` (V0.4). None of
these is installed: a second primitive system would be a second source of truth
for focus, portals and layering.

## New treasures discovered this round

| Project | What it is | Why it matters here |
| --- | --- | --- |
| `rolldown/tsdown` | Rolldown-powered library bundler with declarations, unbundle mode and optional `publint`/`attw` hooks | The reason the package can be both compiled and genuinely tree-shakeable |
| `noahfschr/dont-clear-url-params` (inspiration only) | A community pattern library for preserving unrelated query parameters | Confirms the `mergeParams` approach: a state helper owns its keys and nothing else |
| The `nuqs` testing adapter | In-memory URL state for component tests | Shaped how the URL codecs are unit-tested (pure functions first, adapter second) |
| `react-resizable-panels`' `data-separator` state vocabulary | State-as-attribute styling | Removed the need for a JS drag state in `WorkspaceResizeHandle` |

## License findings

Every adopted package is MIT. Verified via the npm registry metadata
(`npm view <pkg> license`) and, for the two that mattered most,
`react-resizable-panels@4.13.3` and `nuqs@2.10.1`, by reading the `license` field
in the packed tarball's `package.json`. `@shadcn/lint@0.2.0` is MIT as well.

No project with a Commons Clause, a paid license or an unknown license was
copied, vendored or adapted in this round. The full matrix, including the exact
verification command, is in `license-matrix.md`.
