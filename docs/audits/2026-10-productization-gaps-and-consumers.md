# LUC UI productization audit — gaps, variants and consumer adoption

Date: 2026-10-08. Findings are tied to source paths. **Verified** describes the code as read; **recommendation** is an implementation choice for a later phase. This audit did not run a new browser or contrast sweep, so a possible accessibility issue below is a review target, not a confirmed violation.

## Design consistency and identity

| Finding | Evidence | Assessment and recommendation |
| --- | --- | --- |
| The system has a recognizable base: restrained cool neutral surfaces, one accent, hairline borders, density and type roles, plus optional interaction effects. This is stronger than a stock shadcn copy, while still using familiar Radix composition. | `luc-ui/packages/ui/src/tokens/tokens.css`, `luc-ui/DESIGN_SYSTEM.md`, `luc-ui/packages/ui/src/components/card.tsx`, `luc-ui/packages/ui/src/motion/index.ts` | **Verified.** Preserve the calm base. Use curated combinations of existing motion primitives for memorable moments; do not reskin every control. |
| Light `surface-default`, `surface-raised` and `surface-overlay` are all `oklch(1 0 0)`, so light-theme depth relies largely on border/shadow; dark-theme surfaces have clearer luminance steps. | `luc-ui/packages/ui/src/tokens/tokens.css` (`:root` and `.dark` blocks) | **Verified.** Evaluate actual screenshots before changing tokens; a light-theme depth adjustment should be scoped and measured, not arbitrary. |
| Size naming is mostly `sm/md/lg`, but Badge/EmptyState/Sheet and motion primitives have family-specific scales. Some are appropriate to purpose, yet developers lack one quick reference showing which knobs are shared and which are intentionally local. | `luc-ui/packages/ui/src/components/{button-variants,input,tabs,empty-state,sheet}.tsx`, `luc-ui/docs/PUBLIC_API.md` | **Recommendation.** Add an API comparison table in the docs, and standardize only genuine same-purpose inconsistencies. |
| `Card` exposes legacy `interactive`/`selected` booleans alongside `interaction: static|interactive|selectable|featured` and `selected`, allowing redundant or conflicting combinations. | `luc-ui/packages/ui/src/components/card.tsx` | **Verified.** Document precedence now; decide a nonbreaking deprecation path only after consumer scan. Prefer `interaction` for new examples. |
| Input and Select share semantic chrome, but Combobox reproduces much of it locally. | `luc-ui/packages/ui/src/components/input.tsx`, `select.tsx`, `combobox.tsx` | **Verified.** Audit focus/invalid/disabled visual states across all three at the same viewport and density; extract only a proven shared recipe. |
| SegmentedControl and SharedHighlight repeat track/thumb radius and spacing with literal pixel radii (`rounded-[5px]`, `rounded-[6px]`, `rounded-[7px]`) while Tabs uses a related sliding indicator. | `luc-ui/packages/ui/src/components/segmented-control.tsx`, `tabs.tsx`, `luc-ui/packages/ui/src/motion/shared-highlight.tsx`, `luc-ui/packages/ui/src/hooks/use-sliding-indicator.ts` | **Verified.** They already share measurement; compare visuals and consider a semantic selected-track recipe/token to reduce drift. |
| Raw `#000` exists in CSS mask strings for effects. It is a mask alpha source, not a visible palette color. | `luc-ui/packages/ui/src/motion/spotlight-surface.tsx`, `interactive-grid.tsx` | **Verified.** Do not flag it as an off-brand color; make the lint exception/documentation explicit if the checker reports it. |
| The disabled button recipe uses whole-control `opacity-45`; text-bearing disabled controls may be hard to read, while the input family deliberately avoids whole-shell dimming. | `luc-ui/packages/ui/src/components/button-variants.ts`, `luc-ui/packages/ui/src/components/input.tsx`, `luc-ui/DESIGN_SYSTEM.md` §3/§7 | **Review target.** Test disabled labels in both themes and high zoom. Any change should preserve a distinct inactive state without reducing necessary text contrast. |

## Core variant and interaction review

| Family | Verified API/behavior | Gap or risk | Later acceptance direction |
| --- | --- | --- | --- |
| Button | 5 intents × 3 sizes, loading, icons, `buttonVariants` for links (`components/button-base.tsx`, `button-variants.ts`). | Inventory says `asChild` but the prop is absent (`docs/COMPONENT_INVENTORY.md`); no direct link composition through Button. | Correct docs first; keep native button and recipe pattern unless a real consumer needs a polymorphic trigger. |
| Input/Select | Shared sizes, Field integration, Radix Select parts (`components/input.tsx`, `select.tsx`, `field.tsx`). | Combobox chrome is partly duplicated (`components/combobox.tsx`); validation visual parity deserves QA. | One state matrix covering focus, invalid, readOnly, disabled, leading icon and compact density. |
| Dialog/Popover/Menu/Tooltip | Radix composition and overlay tokens (`components/dialog.tsx`, `popover.tsx`, `dropdown-menu.tsx`, `context-menu.tsx`, `tooltip.tsx`). | Some families have no direct unit test; Tooltip assumes provider; nested overlay behavior is mostly browser-QA territory. | Document trigger/portal/focus contracts and maintain an overlay interaction fixture across mouse, keyboard and touch. |
| Tabs/selected controls | Radix Tabs, ToggleGroup and measured shared indicator (`components/tabs.tsx`, `segmented-control.tsx`, `motion/shared-highlight.tsx`). | `SharedHighlight` gives underline containers `role="tablist"` but renders links with `aria-current` or buttons with `aria-pressed`, rather than tab roles (`motion/shared-highlight.tsx`). This may be an invalid semantic mix. | Verify in browser accessibility tree; either use true tabs with panels or a named navigation/group role for link/button selectors. |
| Card | Surface/interaction modes and polymorphic native tag (`components/card.tsx`). | `interaction` and `interactive` overlap; clickable `div` is possible without native keyboard semantics. | Document that actionable cards use `as="a"`/`button` with a name; clarify precedence. |
| DataTable | Sort/filter/pagination/selection/pinning/virtualization and formatting helpers (`table/index.ts`, `table/table-core.tsx`). | Inventory describes “`role=grid` semantics” but implementation renders native `<table>`; no spreadsheet-style keyboard navigation or cell editing (`table/data-table.tsx`, `virtual-data-table.tsx`). | Correct docs; keep semantic table contract. Treat editable DataGrid as a separate evidenced need. |
| Sidebar/Workspace | Responsive rail and mobile drawer; resize handle and persistence (`app-shell/sidebar.tsx`, `workspace/workspace.tsx`). | No arbitrary docking or tear-off panes; this is an intentional narrower workspace model. | Extend only from a product-independent use case. |
| Motion | Multiple opt-in effects and reduced-motion tokens (`motion/index.ts`, `styles/base.css`). | The number of effects raises misuse risk; no clear per-component “when to use” chooser in the public API list. | Publish a motion decision guide with budgets and forbidden pairings. |

**Missing variants are distinct from missing components.** No evidence supports adding another Button family, modal family, or table family now. Likely variant/documentation work is: focused/invalid/readOnly parity for input-like controls, Card interaction precedence, a quiet/featured motion usage matrix, and a tested density variant for data-heavy tables. The public gaps that would require new families (DataGrid editing, freeform multi-select Combobox, drag-and-drop docking) should wait for a concrete consumer and data/keyboard contract (`luc-ui/docs/COMPONENT_INVENTORY.md`, `luc-ui/docs/WORKSPACE_GUIDE.md`, `luc-ui/packages/ui/src/table/index.ts`).

## Data and workspace UI

**Verified:** ECharts is loaded through the modular runtime and generic `Chart`/`ChartSpec` family; Lightweight Charts has `LightweightSurface` and `FinancialChart`; TradingView wrappers are isolated under their own subpath and typed catalog (`luc-ui/packages/ui/src/charts/index.ts`, `luc-ui/packages/ui/src/charts/adapters/echarts/runtime.ts`, `luc-ui/packages/ui/src/charts/adapters/lightweight/lightweight-surface.tsx`, `luc-ui/packages/ui/src/charts/financial/financial-chart.tsx`, `luc-ui/packages/ui/src/integrations/tradingview/core/catalog.ts`). `ChartSyncGroup`, cursor/range bus, pin/keyboard inspection, annotations, range/scale chrome, PNG export, fullscreen and chart/table alternates exist (`luc-ui/packages/ui/src/charts/chart-card.tsx`, `luc-ui/packages/ui/src/charts/core/sync.ts`, `luc-ui/packages/ui/src/charts/core/inspection.tsx`, `luc-ui/packages/ui/src/charts/types.ts`, `luc-ui/packages/ui/src/charts/components/{chart,chart-toolbar,fullscreen,chart-data-table}.tsx`). The chart family's exact source files carry family-specific props; `luc-ui/docs/CHART_GUIDE.md` is the integration guide.

**Partial:** `ChartDataTable` offers a semantic alternate, but a generic linked data-inspection layout combining chart, rows, active datum and export is a recipe rather than one composition API (`src/charts/components/chart-data-table.tsx`, `src/data/data-details.tsx`, `apps/showcase/app/patterns/chart-table/page.tsx`). Annotation *rendering* exists through `AnnotationSpec`; an annotation editor, persistence, collision policy and keyboard authoring do not (`src/charts/types.ts`, `src/charts/components/chart.tsx`). `Workspace` provides split panes and local sizes, not arbitrary docking or document-level workspace persistence (`src/workspace/index.ts`, `src/workspace/use-workspace-layout.ts`). The Command surface exists; application command ownership/registration across many features is not a generic registry (`src/components/command.tsx`, `src/app-shell/navigation.ts`).

**Recommendation:** Improve the linked inspection recipe and its controlled-state API only after validating it in at least two generic example contexts. Keep crosshair, selection and visual overlays as UI state; prepared series and annotations come from consumers. Do not put financial calculations in the package. Reserve docking and editable grids for later evidence; their keyboard, persistence and accessibility contracts are substantially larger than a styling extension.

## Luc Web consumption, read-only

The scan found 214 lines matching `from "@luc/ui` in `luc-web` TypeScript/TSX files; this is an import-line count, not a count of distinct symbols or shipped routes. The product consumes the public subpaths for shell, controls/forms, data/table, charts/financial chart and TradingView (examples: `luc-web/components/public/public-shell.tsx`, `luc-web/components/admin/block-inspector.tsx`, `luc-web/components/render/{time-series-chart,financial-chart-island,tradingview-island,payload-table}.tsx`). This is a real cross-project consumer, so changes to these APIs need a Luc Web compatibility gate.

| Local pattern | Evidence | Boundary decision |
| --- | --- | --- |
| Page tabs render a link-based underline and use only LUC's `useSlidingIndicator`, rather than Radix Tabs. | `luc-web/components/public/page-tabs.tsx`, `luc-ui/packages/ui/src/components/tabs.tsx` | **Potential generic promotion:** a navigation-link indicator recipe could extend `SharedHighlight`, but first fix/verify its semantics and preserve Next route behavior. |
| Universal search trigger composes its own input-like chrome while the palette uses LUC Command. | `luc-web/components/public/universal-search.tsx`, `luc-ui/packages/ui/src/components/{search-input,command}.tsx` | **Potential generic recipe:** search-trigger styling; keep route lookup and result ranking in Luc Web. |
| Chart inspection/share/scale controls and legend state are composed locally from LUC primitives. | `luc-web/components/render/{chart-inspect,chart-share,chart-scale,series-legend}.tsx` | Extract only engine-agnostic state/chrome proven useful elsewhere; chart content and URL semantics stay in Luc Web. |
| `DataSurface`, metric blocks, indicator views, research narrative and Signal state are product composition. | `luc-web/components/render/{surface,metric-block,indicator-surface,research-block,signal-block}.tsx` | Keep in Luc Web: these encode payload and domain meaning. `Card`, `Metric` and `Chart` remain generic LUC layers. |
| `PublicShell` injects product brand, search, locale and routes into LUC AppShell. | `luc-web/components/public/public-shell.tsx`, `luc-ui/packages/ui/src/app-shell/app-shell.tsx` | Keep the injection boundary; do not put Luc Quant route/config logic into `@luc/ui`. |

**Consumer validation recommendation:** for a future UI change, run package `pnpm verify` and targeted Showcase QA, then Luc Web `pnpm verify` and affected route QA. Review dark/light, compact density, responsive layouts, keyboard, reduced motion, hydration and chart-engine isolation using the existing scripts (`luc-ui/package.json`, `luc-ui/docs/QA_WORKFLOW.md`, `luc-web/package.json`, `luc-web/qa/`). The present audit did not run those gates because no implementation changed.

## Quality and package-readiness analysis

| Area | Verified | Remaining evidence or risk |
| --- | --- | --- |
| Export/type contract | Source/publish export maps and declarations checked by package scripts (`packages/ui/package.json`, `tsdown.config.mjs`, `scripts/verify-package.mjs`). | Verify from a truly independent install outside the monorepo before distribution. |
| Peer dependencies | React/React DOM 19; React Hook Form optional peer (`packages/ui/package.json`). | Decide whether React 19-only is the intended external audience; do not broaden blindly. |
| Styles/tokens | CSS side effects declared, source scanning via `@source`; postbuild copies CSS (`src/styles/index.css`, `package.json`, `scripts/postbuild.mjs`). | Independent Tailwind v4 install needs a tested `dist` scan path. The README example currently says `@source "../node_modules/@luc/ui/src"` while packed tarballs omit `src` (`README.md`, `scripts/verify-package.mjs`): documentation drift. |
| Tree shaking / weight | Separate heavy subpaths, unbundle build, consumer isolation and baseline script (`src/index.ts`, `scripts/consumer-test.mjs`, `bundle-baseline.json`). | Re-run measured budgets for any new import; root barrel should remain convenient, not the default for expensive islands. |
| SSR/hydration | Server-safe recipe split, theme init script, locale/date rules and client modules (`components/button-variants.ts`, `providers/theme-script.ts`, `datetime/index.ts`). | An independent Next/Vite consumer matrix would catch hydration/CSS issues not visible in this workspace. |
| Accessibility / motion | Radix and React Aria behavior, base reduced-motion clamp, chart table alternate and browser axe harness (`src/styles/base.css`, `src/charts/components/chart-data-table.tsx`, `apps/showcase/qa/`). | Review SharedHighlight semantics and disabled-button contrast; provider and canvas interiors remain limited. |
| Browser/visual QA | Showcase routes, deterministic behavior checks and committed baselines (`apps/showcase/qa/`, `artifacts/baselines/`, `docs/QA_WORKFLOW.md`). | Baselines cover selected views, not every variant/theme/state; build a risk-based matrix rather than a screenshot for every combination. |
| Distribution policy | Package manifest says `license: UNLICENSED` and V1 docs call API stable (`packages/ui/package.json`, `docs/PUBLIC_API.md`). | Before any future npm release, resolve license/commercial terms, support matrix and semantic-version policy; this audit changes none of them. |
