## C. 根因（共享缺陷）

1. **RC1｜custom 序列缺少 `encode`**：Gantt 是库中唯一"自定义序列独占 x 轴"的图表，
   ECharts 默认 dim0→x，于是时间轴域取到了**行号**（0…3 ms）——既导致 1970-01-01 的
   "Jan 1" 刻度，也让所有任务条被映射到域外裁掉。修复：`encode: { x: [1, 2], y: 0 }`。
   其余自定义序列已逐一核对（有兄弟序列定域或轴固定），确认不受影响。
2. **RC2｜`arcPoints` 每个圆弧都输出 `M`**：路径拼接后成为**两条子路径**，填充时各自闭合，
   于是和弦缎带变成"贴圆的月牙"、圆环带中间出现空洞。修复：返回点集，由调用方写唯一的
   `M`、沿源弧折线、经圆心的二次曲线、目标弧、`Z`。
3. **RC3｜像素尺寸被当成百分比**：ScatterMatrix 的格子宽度写成 `cellSize / 100` **百分
   比**（默认 120 → 1.2%），12 个格子变成邮票；同时没有为刻度预留边距。修复：格子为
   `100 / n`%，`containLabel` 预留标签区，每轴 3 段分割（实测 5 段会连成一串）。
4. **RC4｜轴域忽略了它要画的标记**：VectorField 的轴域只覆盖采样点，而箭头延伸到
   `采样点 + (u,v)·scale`，越出格点的箭头被裁掉。修复：域覆盖尾端与尖端并留 8% 余量，
   箭头头部设 5px 下限。
5. **RC5｜标签不考虑可用空间**（四个不同位置的同一个错误）：树的标签位置默认是 `left`；
   旭日图内环强行水平排字；历史位置读数无边界；bump 轴名画在轴端与首个刻度同角。
6. **RC6｜舞台根本不存在**：CardStack 每层都是 `absolute inset-0`，组本身没有高度，演示
   只给了宽度 → 卡组 0px 高、溢出到代码块、控件叠在卡上。修复：默认 `min-h-60` 舞台 +
   覆盖层改为底部排布。

## F. 语义正确性测试

新增 `src/charts/components/visual-correctness.test.tsx`，**13 条语义断言**，全部在修复前
必然失败、修复后通过。断言对象是"引擎收到的 option"与"组件的布局决定"，而非"画布存在"：

- Gantt：`encode.x` 必须是时间维度 `[1,2]`，x 轴必须是 `time`，每根条 `end > start`；
- ScatterMatrix：格子数 = n×(n−1)，宽度 = `100/n`%，每个序列的 x/y 变量与格子命名的变量
  逐一对上（并按行读取真实数值）；
- Chord：每个形状恰好一个 `M` 且以 `Z` 结束；
- VectorField：轴域覆盖尾端与尖端；
- HierarchyTree：标签位置随方向、边距随位置迁移；
- Sunburst：内环 `minAngle ≥ 20`、`hideOverlap` 生效；
- Bullet：`min = 0`、轴上限留出标签空间、读数标签在条端、靶标尺寸；
- Calendar：图例不在顶部而 `bottom ≤ 4`、逐格边框为 0、图例带数值文本；
- Surface3D：文字数量与 z 轴名存在、多边形数 = 1 + 2×格子数；
- HistoricalPosition：靠边时贴边、居中时 `translateX(-50%)`。
